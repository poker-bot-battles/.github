# About Poker Bot Battles

Poker Bot Battle is an exciting annual event, where a good poker face is not enough!
We will be playing No Limits Texas Hold'em and you will have to create you best poker-playing algorithm to come out on top.
Your algorithm can be made either in Java or Python and worry not; We have guides for setting up and joining the competition as well as how to play poker.
Teams are allowed, but you must bring at least one computer to the event for your team!

## How the event goes
- Round Two: Poker Playground
  In the first round you will have to develop your own PokerBot.
  We will give a short introduction to how you get started and how you play poker.
  You will be able to test your PokerBot locally and see how well it perform.

- Round Two: Preliminary Rounds
  In the preliminary rounds you and your bot will be pitted against the people on your table.
  This is where it gets real and your bot needs to win against other real players.
  
- Round Three: The Finals Table
  All the winners from the preliminary are gathered for a final game at the winners table.
  All is shown on the big screen.
  This is the big finale, and everyone will be watching as we find one to rule them all!
  Lastly is a price handouts for the winner(s) and the runner-uos.

## Good to know
We operate under some standards when it comes to making changes to the codebases. 
These sound more scary than they are and if you feel overwhelmed we highly encourage just talking to us and we will gladly help.

### Git
We use git and thus follow some of the common conventions seen when using git.
All the information can be found at [conventionalcommits](https://www.conventionalcommits.org/en/v1.0.0/).

**Tl;dr**
A git commit should look like this

```
<type>[optional scope]: <description>

[optional body]

[optional footer(s)]
```

_Where_
- `<type>` is either `feat`, `fix`, or `docs`.
- `[scope]` can further specify the type, i.e. `fix(security)`
- `description` is a short description of the commit
- `[body]` is where you leave any other information needed to understand the changes you've made
- `[footer(s)]` is metadata like who made the code.

Thus a commit will look like
```
fix(security): Added validation of file upload

Added validation of file type on the upload on /submit-bot.
Legal file types are now .py and .java

Author: Ellie Kulmbak <ellk@itu.dk>
```
